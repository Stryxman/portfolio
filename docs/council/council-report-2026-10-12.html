Conseil LLM : plan du portfolio

Le plan (Next.js 16 + Convex + admin maison, Better Auth, Vercel Hobby, direction « Ordre et transformation » avec moteur WebGL2, V1 complète) est-il le bon pour un site durable, rapide, gratuit, qui démarque Richard ?

Recommandation : garder la direction visuelle et le moteur « Champ », mais remplacer la base Convex + admin + auth de la V1 par un site statique alimenté par des fichiers dans Git (édités via Claude Code, avec Keystatic en option pour une admin sans base), hébergé gratuitement chez un hébergeur qui autorise l'usage commercial. Convex reste une V2, déclenchée seulement par un besoin mesuré.

Où le conseil converge

  • L'admin résout un problème que tu n'as pas : tu publies déjà en demandant à Claude Code d'ajouter un fichier puis en poussant. La cible du PRD (« publier en moins de 5 min ») est atteinte sans admin.
  • Trop de services pour un seul éditeur : 7 services gratuits, plusieurs briques en 0.x. C'est l'inverse de « durable ».
  • Vercel Hobby n'est pas compatible avec un site qui sollicite des clients. Cloudflare ou Netlify autorisent l'usage commercial gratuitement.
  • Ce qui te démarque, c'est le Champ et les sceaux, pas le CRUD. L'effort doit y aller, et au contenu.

Check de divergence

Convergence élevée : possible biais commun, confiance à tempérer. Les tensions attendues ne se sont pas matérialisées (l'Expansionist rejoint le Contrarian). La question cadrée mentionnait « Node non installé » et « Claude Code comme outil principal », ce qui a pu orienter tout le monde vers la même lecture. Et les cinq ont écarté une exigence que tu as formulée : une interface admin et un site « entièrement dynamique ».

Où le conseil se déchire

  • Astro ou Next.js : 4 conseillers sur 5 préfèrent Astro (site de contenu, statique par défaut, îlots interactifs). L'Outsider garde Next.js + Keystatic. Le moteur WebGL étant indépendant du framework, ce choix n'affecte pas l'identité visuelle.
  • Admin ou pas : Contrarian, First Principles et Executor la suppriment ; Outsider et Expansionist acceptent Keystatic (admin qui écrit dans Git, sans base). Le critère : modifieras-tu le site depuis un téléphone, sans Claude Code ?

Angles morts attrapés

  • Le « dynamique » demandé se fait sans base : sync GitHub par reconstruction quotidienne (GitHub Actions planifiée, gratuite), captures d'écran générées dans la même action, contact par une fonction serverless.
  • Idée de l'Expansionist : générer les fiches projet depuis les dépôts de Local/ (README + CLAUDE.md). Le portfolio suit ton travail réel.
  • Chaque sceau génératif peut devenir l'image de partage (LinkedIn, GitHub) de son projet, et le moteur une signature réutilisable sur tes sites clients.
  • IMPLEMENTATION_PLAN.md est cité mais pas encore écrit (normal à ce stade, prévu après ta relecture).

Ce verdict changerait si…

  • tu prévois de publier plusieurs fois par mois depuis un téléphone ou une machine sans Claude Code (alors Keystatic, voire Convex) ;
  • tu veux à court terme des fonctions qui exigent une base : comptes, espace client, statistiques maison.

La première chose à faire

Répondre aux deux questions décisives (édition depuis mobile ? rythme de publication ?), puis un essai chronométré d'une journée : Node + Astro + 3 vrais projets en fichiers + déploiement Cloudflare. Succès si ajouter un 4e projet via Claude Code prend moins de 5 min jusqu'à la mise en ligne et si Lighthouse mobile ≥ 95. Sinon, le plan Convex est justifié.

Avis complets

Contrarian · Opus · pre-mortem

Échec à 12 mois : trois mois à monter Convex, Better Auth et 8 modules d'admin ; sortie tardive, fiches EN vides ; mise à jour d'auth qui casse l'admin au mois 9, jamais réparée. Hypothèse fragile : « modifier le code freine les mises à jour », fausse avec Claude Code. Briques en 0.x, six services à clés et quotas, sauvegarde manuelle vite oubliée, Vercel Hobby incompatible avec le persona client. Info manquante : rythme d'ajout (moins de 2 par mois → l'admin ne s'amortit jamais). Test : Astro + Markdown + 5 projets sur Netlify en une journée ; 6e projet en moins de 5 min et Lighthouse ≥ 95.

First Principles · Opus · base rates

Le vrai problème est d'être compris vite puis contacté (7,4 s pour le premier tri d'un CV, Ladders 2018 ; pas de chiffre fiable pour un portfolio). L'admin, près de la moitié de la V1, n'est vue par aucun visiteur. Les offres gratuites disparaissent (Heroku 2022, PlanetScale Hobby 2024) ; un site statique survit à n'importe quel fournisseur. Réfuté si l'ajout prend plus de 5 min ou si 4 publications par mois depuis un téléphone sont prévues.

Expansionist · Sonnet

Ton meilleur CMS existe déjà : dépôts Git, README, CLAUDE.md, gh. Un script peut produire les fiches depuis Local/. Le Champ et les sceaux sont l'actif rare : images OG partageables, micro-bibliothèque, signature vendue avec chaque site client. Le portfolio devient la démo et le gabarit commercial. Test : Astro + MDX depuis 3 README + Champ ; ajout en un prompt en moins de 2 min, Lighthouse ≥ 95 moteur actif.

Outsider · Haiku

Le plan sacrifie la durabilité à l'ambition technique. Une suspension Vercel ruinerait la crédibilité ; Netlify règle le problème. « Durable + seul + stack sur mesure » est contradictoire : qui maintient l'admin dans 6 mois ? Test : lire la clause Vercel (5 min) ; V0 Next.js + Markdown + Keystatic + contact ; si un changement prend plus de 4 h, la stack est trop complexe.

Executor · Sonnet

Projet d'ingénierie plutôt que portfolio : couper en deux. Le goulot est la mise en ligne : 0 ligne de code, Node absent, 7 services externes. Prédiction : le plan actuel ne sera pas en ligne dans 6 semaines. Le moteur visuel, ce qui démarque, devient un lot séparé après la mise en ligne. Test : fnm + Astro + 3 projets + Cloudflare Pages, en ligne en 4 h ou moins, Lighthouse ≥ 95, 4e projet en moins de 5 min.
